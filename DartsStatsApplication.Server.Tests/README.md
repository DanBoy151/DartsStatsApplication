# DartsStatsApplication.Server.Tests

Minimal test project added as Stage 2 of the remediation plan (test harness + CI, before Stage 3's validation-logic work).

## What's covered right now

`GameControllerValidatorTests.cs` covers `GameControllerValidator.ValidateSelectedPlayers()` — the only validator method that currently has real logic *and* doesn't touch the Marten `IDocumentSession`, which makes it safe to unit test with a `null` session and no database.

## What's intentionally not covered yet

- `MatchControllerValidator.IsValidToStartMatch()` and `ValidateAvailablePlayers()` have real logic too, but both query `_documentSession` directly, so testing them properly needs a real Marten/Postgres-backed session (e.g. via Testcontainers) rather than a null one.
- `GameControllerValidator.IsValidToStartGame()` / `IsValidToCompleteGame()`, `LegControllerValidator.IsValidToCompleteLeg()`, and `MatchControllerValidator.IsValidMatchToComplete()` / `IsValidPlayerOfMatch()` are still empty stubs — there's no logic to test yet.

Both of these are deferred to Stage 3 of the remediation plan, where tests should be written alongside the real implementations rather than against stubs or with database mocking set up prematurely.

## Note on this project's provenance

This project's files were hand-authored (matching the standard `dotnet new xunit` template output) rather than generated by running the .NET CLI, because no `.NET SDK` was available in the environment used to create them. **Run `dotnet restore` and `dotnet test` locally before relying on this** — package versions in the `.csproj` should be treated as a reasonable starting point, not verified-working pins, and this is genuinely the first time this project has been built or tested anywhere.
